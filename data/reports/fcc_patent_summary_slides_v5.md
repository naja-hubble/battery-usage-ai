# エグゼクティブサマリ

- **課題**: SoH表示を駆動するFCCが更新されない『ゲージ凍結』は、静的検査では正常/要再較正/FW疑いを判別できない。752台中114台が凍結、うち70台は使用で説明不能。
- **解決**: 『凍結を予測』は失敗(AUC≈0.54=コイン投げ)。『再学習の機会に応答したか』をEND起点72h窓で機械的に監査する方式へ転換。テレメトリのみ・機種非依存・欠測に頑健・30日保持で全期間と等価。
- **実績**: 全履歴監査でゲージ18台/FW14台に自動振り分け(既存active層からの誤エスカレーション0件)。オンライン版はCore判定 proxy精度1.0・能動誤報0件。5本柱の独立検証で技術効果を実証。
- **特許候補**: ①機会条件付き無応答監査 ②デュアルトラック非対称リセット ③有界保持の因果証拠台帳 + 将来④⑤。①〜③の技術エビデンスはSTRONG、ただし新規性リスクは別軸(UNVERIFIED)。
- **依頼**: (1)粒度・範囲の判断 (2)候補②の着想日・公開有無の確認 (3)正式FTO/特許性調査の発注判断 (4)介入データ収集開始の判断

💡 『動くべき機会に動かなかった』事実だけを、欠測に騙されず数える監査技術。エビデンスは強いが、特許性(新規性)の判断はここから先が本番。

# §1 基礎① ノートPCバッテリと『燃料計』

| 用語 | 意味 | 身近なたとえ |
|---|---|---|
| FCC（満充電容量） | 『いま満タンでどれだけ入るか』の学習値(mWh)。劣化で減る | 何度も計り直して覚える『いまの満タン量』 |
| RSOC（相対残量） | いまの残量% = 残容量÷FCC×100 | ガソリンメーターの針 |
| SoH（健全性） | 健康度% = FCC×100÷設計容量 | 新品比の容量% |
| FCC学習（再較正） | 『満充電→深く放電→再び満充電』のときだけ計り直せる | 体重計のゼロ点合わせ |
| ゲージ凍結 | FCCが長期間更新されない。SoH表示も止まる | 校正が止まり表示が古いまま |

- 実容量は直接測れない。ゲージICが充放電から推定 / FCCは整数mWh量子化(最小10mWh)で階段状
- SoH・残り時間・保証判断は全てこの学習値に依存

💡 PCの電池残量・健康度表示は『実測』ではなく『燃料計チップの学習値』。学習が止まると表示だけが古いまま取り残される。

# §1 基礎② FCC学習のしくみと『ゲージ凍結』

- **学習機会**: RSOC 高(≈80%)→低(≈20%)→高(≈80%) の往復1サイクル。燃料計はこのときだけFCCを計り直せる
- **健全なゲージ**: 学習機会のたびFCCを更新し、実容量の低下を階段状に追いかける
- **凍結したゲージ**: FCCが横ばいのまま。SoH・残り時間・保証判断の元データが古いまま固定
- **難所**: 凍結は故障とは限らない。浅い使い方で機会が無いだけかもしれない

💡 動かない理由が『チャンスが無い』のか『チャンスに応えない』のかが本質的な問い。

---

# §1 基礎③ なぜ問題か

- SoH表示が古いと（定性・金額効果は未算定）: 劣化見逃し→突然のシャットダウン / 健全電池の誤交換→無駄コスト / 保証・リース判断の歪み / フリートで累積
- 実フリート752台: **凍結114台(15.2%)** = stale 59 + very_stale 55
- うち使用で説明可 44台（常時AC 22 / 低サイクル 16 / 浅放電 6）
- **説明不能（HW/FW疑い）70台**: activeより多くサイクル(96.9 vs 65.7 cyc/yr)・深く放電(min RSOC=1)するのに凍結。※『疑い』であり確定診断ではない(FWバージョンデータ不在)

💡 原因はユーザー起因〜FW疑いまで様々で対処も違う。見分ける仕組みがないと保守が空回りする。

---

# §2 用語定義 (1/2) — バッテリと学習機会

- **FCC**: 燃料計が学習する『今の満充電容量』(mWh)
- **FCC更新停止/ゲージ凍結**: FCCが長期間更新されない状態。本技術の判定対象
- **RSOC**: remainingCapacity/FCC×100
- **学習機会/エピソード**: RSOC high→low→high の1サイクル
- **START/LOW/END**: 開始/谷/終了(再充電完了)。END=機会の完了時刻
- **有効ステップ(≥50mWh)** / **micro-step(<50mWh)**: 学習応答とみなす変化 / 微小変化(ノイズとは呼ばない)
- **応答ステータス(END後72h窓)**: responded / no_response(窓を全観測して無し) / censored(観測が途中で終了=保留、無応答に数えない)
- **品質ティア**: HIGH_OK / MEDIUM_GAP / LOW_LARGE_GAP

# §2 用語定義 (2/2) — 検証手法と統計

- **対照/ヌル分布**: 効果が無い場合の期待分布。95%区間の外なら『偶然では説明できない』
- **負の対照検定(A2)**: ニセ機会5種と比較（治験のプラセボに相当）
- **アンカー比較(A3)**: 起点START/LOW/ENDの因果汚染を定量化
- **応答ハザード(B)**: END後経過時間に対する累積応答率(CIF)
- **欠測ストレス(E)/保持グリッド(D)**: 欠測注入耐性 / 短保持と全期間の等価性
- **user-bootstrap**: ユーザ単位再標本(過小評価防止)
- **dual-track/非対称リセット**: any系統とeffective系統を分離、microはany系統のみリセット
- **stateful/stateless**: 永続状態(台帳)あり/なし
- **AUC**: 1.0=完璧、0.5=コイン投げ
- **proxyラベル**: 本番システム出力を仮の正解としたもの

# §3 本来の目的と、なぜ難しいか

**目的**: テレメトリだけからゲージ凍結個体をフリート規模で正しく判定する。

- 静的検査では『浅充放電で正常/要再較正/FW・HW起因』を区別不能
- 欠測・睡眠ギャップ・打ち切り: データの穴を『無応答』と誤判定しやすい
- 生データ保持が有界(直近30日等)で過去の証拠が失われる
- 機種非依存が必須(機種名ハードコードは過学習)

💡 『FCCが動かない』結果は同じでも原因は3通り。原因ごとに正しい対処が違う。

# §3 失敗した素朴アプローチ → 発想の転換

- 教師あり予測(33特徴量, 公平比較領域 obs≥180d): **AUC 0.535/0.540** — ほぼランダム
- FCC履歴を除いた規範ML: **AUC 0.5584** — near-random
- 最重要特徴 min_rsoc は『深放電ほど凍結』という反usage方向(交絡)

**発想転換**: 『凍結を当てる』のではなく『再学習する“機会”に対して実際に応答したかを機械的に監査する』(決定論カウンタ)。

💡 壊れそうかをAIに予言させるのは失敗(コイン投げ並み)。『チャンスに応えたか』を出席簿のように数える方式に切り替えたら解けた。

# §3 提案手法の全体像

入力: RSOC / FCC / cycleCount / timestamp のみ（HW識別子は不使用）。

1. **学習機会の抽出**（RSOC high→low→high）
2. **END起点で応答監査**（END後72h窓の有効ステップ≥50mWh）
3. **欠測/打ち切り耐性**（段階品質ティア＋censored除外）
4. **二分岐トリアージ**（機会反復×無応答→FW / 機会皆無→ゲージ再較正）
5. **有界保持で証拠保全**（最小状態の因果台帳、30日保持で全期間等価）

対応: ①+③+④→候補① / ②→候補② / ⑤→候補③。

---

# §3 仕組み図解A — 学習機会と『END起点72h監査』

- RSOC模式波形: 80%帯から20%帯へ放電し再び80%帯へ（START/LOW/END）
- ENDから72hの監査窓で判定: **responded**(有効ステップ観測) / **no_response**(窓を全観測して無し) / **censored**(窓の観測が途中で終了→保留、数えない)
- 期限は『窓を全部観測できたとき』だけ発火(未来情報も使わない)
- 起点をSTARTにすると放電途中の変化まで誤計上(56%汚染)。ENDなら構造的に0%

💡 採点は試験が終わって(END)から72時間だけ。途中退室(censored)は不合格に数えない。

# §4 根拠①〜⑤（図解説の要点）

- **A2** (negative_control_true_vs_null): 実測0.39はどのニセ機会(0.25〜0.31)の95%区間上端も超える(5/5、bootstrap方向一致4/5)。対象2298機会/289ユーザー。
- **A3** (response_anchor_contamination): START起点56%汚染 / LOW 27% / END 0（endの赤棒が無い=ゼロ）。END=0は定義から従う構造的性質。重複帰属≈22%は候補③のseen_idsで防ぐ。production一致率0.93。
- **B** (response_hazard_true_vs_pseudo): 真CIFが常に上(72hで0.39 vs 0.29、差+0.10)。応答中央値≈49h→72h窓は妥当。
- **E** (missingness_false_escalation): 18 regime注入で naive平均643件誤確定 → 提案4.1件(99%減)、機会回収率0.97。binary gateは見逃し側に振れる。
- **D** (retention_invariance_heatmap): statefulは保持7〜90日すべて一致1.00。statelessは7日で0.62。stateful検証 recall 1.0/重複0/MAE≈0.02、ストレージ比0.0417(全1176構成)。

# §5 特許候補① 機会条件付き無応答監査（IC1+IC6相当）

- **背景**: FCC再学習は学習機会でしか起きないが、機会有無と応答有無は静的検査で分離不能
- **問題**: 凍結が『機会なし(正常/再較正)』か『機会あるのに無応答(FW/HW疑い)』か判別できない
- **解決法**: 機会抽出→END起点72h窓で responded/no_response/censored 分類→品質ティア+censor除外→二分岐
- **特許性**: A2特異性・A3汚染0・E欠測耐性で実証。【リスク】非発生イベント監視は広い先行技術→狭め/中位(80/20/80・72h・50mWh・censor除外明示)で出願推奨
- **必要特徴量**: RSOC/FCC/cycleCount/timestamp(raw) → episode・有効ステップ・応答ステータス・品質ティア・二分岐スコア(派生)。識別子不使用

---

# §5 特許候補② デュアルトラック非対称リセット（IC2+C3相当）

- **背景**: 量子化最小10mWh。micro(<50mWh、58.1%)とeffectiveが混在（二峰: モード14 / 217mWh）
- **問題**: 1系統だとmicroステップが未解決の無応答証拠を消し、FW疑いを見逃す
- **解決法**: any系統(任意変化でリセット)とeffective系統(≥50mWhのみリセット)を分離。microはany系統のみリセット(非対称)。同時刻は complete<reset<deadline
- **特許性**: C2アブレーション — 対称は保留1802+確定無応答462件を281ユーザーで消去、非対称は0。ハード指示209→97(112件をソフト較正へ)。**【リスク高】production実装済(v4は特徴付け/検証)+deadbandは一般先行技術→着想日依存**
- **C3**: GMM谷=35.2mWh(CI[26.3,54.1])、50mWhは谷の上・CI内。※50mWhは事前指定値、データは『矛盾しない』ことの独立裏付け

# §5 特許候補③ 有界保持下の因果証拠台帳（IC5相当）

- **背景**: 生テレメトリ保持は有界(例:30日)
- **問題**: 窓をまたぐ機会の証拠が失われる/二重計上（台帳なし7日保持で一致率0.62・recall 0.81・重複2.1）
- **解決法**: 部分FSM・pending期限・seen_ids・直近any/effective変化・gap/censorカウンタ・順序規則(全7要素)を永続化し因果リプレイ。期限は窓観測時のみ発火
- **特許性**: Dグリッド(1176構成)で recall 1.0・重複0・MAE≈0.02 をストレージ比4.2%で達成。最小状態アブレーションで全7要素の必要性を実証。【リスク】streaming+cachingは既知組合せ→『最小状態構造』をクレーム核に

💡 レシートは30日で捨てても、7項目の家計簿があれば全履歴と同じ結論。『どの7項目か』の特定と必要性実証が発明。
